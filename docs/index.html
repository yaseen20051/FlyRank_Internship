Abstract

This study asks whether early search-performance and content-age signals can help rank eligible content items for investigation when organic-search clicks later decline. We construct a page-level March 2026 dataset from the FlyRank ML Internship pseudonymized warehouse, using March 1–15 as the feature window and March 16–31 as the outcome window. A fixed early-signal rule is compared with Logistic Regression and Random Forest using a client-group holdout, with a ≥20% reduction in clicks per measured day serving as a proxy outcome. In the recorded held-out results, Logistic Regression achieved Precision@20 of 0.70, compared with 0.50 for the Week-5 baseline implementation, while Random Forest also achieved 0.70. These findings support a human-reviewed investigation queue, not causal claims about content refreshes or guarantees of future performance.

1. Introduction and problem statement

Content and SEO teams cannot investigate every page with equal depth. The operational decision addressed here is: which eligible content items should a reviewer inspect first when the available early signals suggest possible future search-performance decline?

The project frames this as a ranking and triage problem. Its output is a priority list with reason codes and suggested checks. It does not automatically rewrite, delete, redirect, or otherwise modify content.

3. Methodology

Outcome definition

The proxy label is 1 when clicks per measured day in March 16–31 are at least 20% lower than in March 1–15, and 0 otherwise. This is an observed change proxy, not a human-verified content-quality or intervention-success label.

Features and models

Early-window features include impressions, clicks, clicks per day, average position, measured-day count, content age, and days since update. Client identifiers are grouping variables, not model features. The learned models are regularized Logistic Regression and Random Forest.

Validation and leakage controls

The headline evaluation uses a client-group holdout (20% test, seed 42), so a client does not appear in both training and test partitions. A random-row split was intended only as a diagnostic and is omitted here because its diagnostic receipt was not saved. Late-window metrics, decline labels, trend fields and other target-derived values are excluded from model features.

Baseline comparability caveat. The frozen Week-4 baseline was documented as log1p(early_impressions). The Week-5 comparison code applies an additional freshness multiplier. Therefore, the Week-5 baseline result below is the implementation actually evaluated in Week 5, not an exact reproduction of the frozen Week-4 rule. A strict apples-to-apples rerun is required to resolve this difference.

5. Limitations and honest framing

  • The outcome is a two-window decline proxy, not a verified diagnosis of content decay.
  • Observed changes may reflect query mix, seasonality, SERP layout, ranking shifts, data coverage or tracking changes.
  • The study uses one March evaluation window. Client grouping does not substitute for multi-month forward-in-time validation.
  • No controlled content-refresh intervention was evaluated; no causal refresh-impact claim is supported.
  • The baseline implementation mismatch described in the methodology limits strict interpretation of the model-versus-frozen-rule comparison.
  • Precision@K is useful for triage capacity but does not by itself establish business value, ROI or intervention success.

Accordingly, the results are observed, directional and decision-support oriented. They should not be interpreted as proof of Google's ranking algorithm or as a guarantee that a recommended edit will recover clicks.

6. Ranked recommendations and action playbook

The Week-7 playbook selects Logistic Regression when its Precision@20 is at least that of the Week-5 baseline implementation; otherwise it retains the baseline. The recorded metrics meet that selection condition. It assigns items to three review tiers using relative ranking percentiles.

Priority tierRanking ruleRecommended human action
Priority reviewTop 20% of selected rankingVerify GSC coverage, query mix, seasonality and SERP changes; then inspect page intent and content.
ReviewNext 30%Review GSC trend and content context; investigate whether the movement is persistent.
MonitorRemaining 50%Recheck in the next reporting window rather than making an immediate change.

Operational archetypes distinguish priority decline review, model/rule disagreement, and monitor cases. They are triage categories, not semantic content clusters. The safe next step is always investigation by a human reviewer. Do not automatically edit titles, metadata, canonicals, redirects or page content.

7. Reproducibility

The project repository contains the weekly notebooks and capstone notebook. The workflow is:

  1. Run the Week-4 baseline notebook to create the initial rule and eligible page snapshot.
  2. Run Week 5 to train Logistic Regression and Random Forest and export held-out predictions and metrics.
  3. Run Week 6 to audit grouped validation, leakage controls and failure examples.
  4. Run Week 7 to create the human-review playbook and aggregate queue summary.
  5. Run the capstone notebook to assemble the research record and verify available receipts.
